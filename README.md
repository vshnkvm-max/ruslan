# Учет товара — панель управления магазином

Панель на основе shop с голубым интерфейсом по предоставленному образцу: боковое меню, показатели, компактная таблица с закупочной ценой и вложениями (остаток × закупочная цена), формы и мобильная навигация. Данные из исходного магазина не копируются.

Веб-панель для магазина обычных товаров: каталог, клиенты, заказы, управленческие финансы, модерация отзывов, условия реферальной программы, информация о магазине и баннеры. Интерфейс на русском, адаптивная вёрстка, поиск, фильтры и CSV-экспорт. Node.js 24+ и SQLite без внешних runtime-зависимостей и сборки.

## Запуск

```bash
cd /workspace/ruslan
node --version # нужен Node.js 24 или новее
npm run admin:create
npm start
```

Сервер по умолчанию слушает `127.0.0.1:3000`. Команда создания администратора генерирует случайный пароль и сохраняет логин и пароль в `.data/initial-admin.txt` с правами `0600`. Сохраните их в менеджере паролей и удалите файл. Повторный вызов не меняет существующий аккаунт.

Можно создать аккаунт с собственными `ADMIN_USERNAME` и `ADMIN_PASSWORD` (не менее 12 символов), передав их через безопасную среду процесса команды `npm run admin:create`. Не добавляйте секреты в Git. Эти переменные не нужны работающему серверу.

```bash
npm run dev    # перезапуск при изменениях сервера
npm run check  # проверка синтаксиса
npm test       # интеграционные тесты HTTP API с отдельной временной БД
```

Опциональная проверка интерфейса в Chromium (временная БД, рабочие данные не меняются):

```bash
npm install --prefix /tmp/shop-browser --no-package-lock --no-audit --no-fund playwright
PLAYWRIGHT_MODULE=/tmp/shop-browser/node_modules/playwright/index.mjs npm run test:browser
```

По умолчанию браузер берётся из `/usr/bin/chromium`; другой исполняемый файл можно задать через `CHROMIUM_PATH`. Переменная `SCREENSHOT_DIR` позволяет сохранить снимки входа, каталога и мобильной версии. Playwright нужен только для этого дополнительного теста.

Каждая облачная задача уже изолирована. Используйте существующий checkout; не создавайте Git worktree без явного запроса пользователя.

Для постоянного размещения на VPS с Ubuntu 24.04 используйте [инструкцию запуска](DEPLOY.md). В репозитории есть готовые конфигурации systemd и Nginx; база хранится отдельно от кода, поддерживаются HTTPS и автозапуск после перезагрузки.

## Страницы товаров и клиентов

- Товары: вкладки категорий и создание категории, поиск и фильтры, собственное фото, название, сохранение порядка в колонке «Сортировка», цена и закупка, количество, вложения, рейтинг опубликованных отзывов и их просмотр, редактирование и удаление. Нажатие на заголовки позволяет сортировать по названию, цене или заданному порядку.
- Клиенты: создание без номера телефона, редактирование существующих данных, сумма заказов без отменённых, количество и дата последнего заказа; статусы «Активный», «В ожидании», «Заблокирован». Есть поиск по имени, телефону или ID, фильтры по статусу, сумме покупок и числу заказов, выбор строк, массовое удаление и CSV-экспорт текущей выборки.
- Удаление скрывает товары и клиентов из рабочих списков; связанные заказы, отзывы и история сохраняются. Миграции базы применяются автоматически при запуске и сохраняют существующие данные.
- «Создать документ» открывает список «Продажа», «Закупка», «Списание» с документами продажи, закупки и списания. Продажа создаёт документ с товарами и списывает остатки при проведении; списание остаётся ручной записью операции. Закупка содержит товары: при проведении увеличивает остатки и обновляет закупочные цены, а оплаченная сумма записывается в расходы. В «Статистике» остаются оценка склада, выручка, себестоимость, валовая прибыль, средний чек и заказы. Показатели клиентов находятся в «Клиентах», рефералов — в «Реферальной программе». Сводка отзывов убрана.

## Что реализовано

- **Статистика:** оценка склада по закупочной цене (включая архив), выручка по выполненным заказам и ручным продажам, известная себестоимость заказов, валовая прибыль, средний чек и статусы заказов. Себестоимость ручных продаж без состава товаров неизвестна и не включается.

- **Товары:** создание без начальных остатков, редактирование, создание и удаление категорий, цены в целых рублях, загрузка до 10 фотографий JPG/PNG/WebP, выбор главного фото, скрытие на витрине, массовое скрытие и удаление, поиск, фильтры, страницы, экспорт текущей выборки.
- **Клиенты:** список, поиск, история заказов, статус блокировки. Это флаг для будущей интеграции; Telegram Mini App пока не подключён.
- **Заказы:** состав, способ получения, клиент и изменение статуса. Начальные остатки равны нулю, поступления оформляются закупками: приём новых заказов и резервирование требуют будущего API оформления заказа.
- **Операции:** единый список закупок, продаж/заказов, списаний и прочих записей с открытием документов. Оплата закупки не дублируется отдельной строкой. Расчёт выручки, себестоимости и прибыли находится в статистике.
- **Отзывы:** публикация и скрытие.
- **Реферальная программа:** сохранение условий и отображение приглашений. Автоматическое начисление, выплаты и учёт referral-кодов при регистрации ещё не реализованы.
- **Редактор:** контакты, описание, заголовок магазина, создание/редактирование/удаление баннеров, видимость, цвет и ссылка.
- **Аккаунт:** вход и выход; настройки аккаунта скрыты из интерфейса.

По умолчанию магазин **полностью пустой**: товары, клиенты, заказы, отзывы, финансовые операции, приглашения и баннеры не создаются. Контакты и описание магазина пусты; реферальная программа отключена, её суммы равны нулю. Учётная запись администратора создаётся отдельно. Перезапуск сохраняет введённые вами данные и не добавляет примеры. Тестовые записи создаются только явно внутри изолированных тестов, не в рабочей базе.

## API для будущего Telegram Mini App

`GET /api/storefront` — публичное представление сохранённой витрины: `shop`, `products`, `banners`. Скрытые товары и баннеры, закупочные цены, клиенты, заказы и финансовые данные не выдаются. `stock` — текущий остаток. Поле `image` содержит URL главного фото `/api/images/UUID` или пустую строку, `images` — упорядоченный массив URL (до 10). Старые ключи иллюстраций остаются совместимыми с API, но интерфейс показывает для них заглушку. Фото автоматически уменьшается до 1000 пикселей и сжимается до 200 КБ; исходный файл — до 10 МБ. Фото хранятся отдельно в SQLite, загружаются по мере просмотра и кешируются браузером; каталог и сохранение товара передают только ссылки. Фото неопубликованных товаров и ещё не сохранённые загрузки доступны только администратору.

Административные маршруты требуют cookie-сессию. После `POST /api/auth/login` сервер возвращает CSRF-токен; передавайте его в `X-CSRF-Token` для всех изменений. `GET /api/auth/me` восстанавливает состояние сессии; `GET /api/bootstrap` загружает данные панели и объект `user` с именем и CSRF-токеном текущей сессии. При открытии панели отдельный запрос `/api/auth/me` не требуется. CRUD поддерживает создание и редактирование товаров и баннеров, статусы клиентов/заказов/отзывов, ручные финансовые операции и настройки.

Витрина Mini App и локальная корзина реализованы (см. раздел GAS Mini App ниже). Telegram `initData`-авторизация, оформление заказов, бот, платежи и доставка — следующий этап. Для них потребуются отдельные серверные маршруты и проверки. Административные cookie и пароли нельзя передавать в Mini App.

## Хранение и размещение

- `DB_PATH` — путь к SQLite, по умолчанию `.data/shop.db` относительно приложения. Для команды `admin:create` запускайтесь из корня проекта; используйте одинаковый `DB_PATH` для сервера и CLI.
- `HOST` — по умолчанию `127.0.0.1`; для контейнера можно задать `0.0.0.0`.
- `PORT` — по умолчанию `3000`.
- `COOKIE_SECURE=true` — обязательно при размещении за HTTPS reverse proxy. Оставьте выключенным только для локальной проверки HTTP.
- БД и файлы WAL должны находиться на постоянном диске с ограниченным доступом. Снимайте согласованные резервные копии SQLite. Не копируйте только `shop.db` у работающего процесса без учёта WAL.
- Пароли хешируются scrypt с индивидуальной солью. Сессии на 12 часов хранятся в БД по хешу токена; cookie — `HttpOnly`, `SameSite=Strict`. Изменения защищены CSRF-токеном, проверяется Origin, вход ограничен по числу неудачных попыток.
- В первой версии нет ролей сотрудников, MFA и журнала действий. Перед публичным запуском настройте HTTPS, резервное копирование, мониторинг и правила доступа. Вход защищает API; публичный API витрины выдаёт только необходимые покупателю поля.

Приложение не требует сетевых запросов к CDN, внешних шрифтов или npm-пакетов при запуске. Опубликовать приложение на домене и настроить Telegram нужно отдельно.

## Архив и описание

По умолчанию в товарах показаны только позиции в работе. Фильтр «Архив» открывает архивные позиции; кнопка «Восстановить» возвращает тот же товар с прежним ID, отзывами и историей. Для нескольких позиций есть массовое архивирование и восстановление. Архив (`active`) и видимость в боте (`visible`) — разные признаки. У каждого товара есть кнопка ✅/❌. Нулевой остаток автоматически скрывает товар, поступление через закупку включает его видимость; архивный товар при этом остаётся в архиве.

Фото заполняет квадратную область с пропорциональным увеличением от центра и обрезкой выступающих краёв. При отображении равномерные белые/прозрачные поля убираются, чтобы центрировался сам объект; исходное изображение в базе не меняется. В редакторах описания товара и магазина доступны H2, H3 и цвет выделенного текста с предпросмотром. Формат хранится как текст: `## Заголовок`, `### Подзаголовок`, `[color=#087fff]текст[/color]`. HTML из описания не исполняется. Потребителям API следует отображать этот ограниченный формат с экранированием текста.

## Просмотры товаров

В «Статистике» показаны выручка, известная себестоимость, валовая прибыль, средний чек, статусы заказов, топ-10 товаров по просмотрам и оценка склада. Оценка склада включает количество единиц, стоимость по розничным и закупочным ценам (включая архив), а также предупреждение о товарах с остатком и нулевой закупочной ценой. Показатели клиентов и рефералов находятся в своих разделах; сводки отзывов здесь нет. Топ-10 расположен внизу слева, оценка склада — справа; на узких экранах блоки идут друг под другом. Рейтинг учитывает сохранённые просмотры за всё время, независимо от выбранного месяца; товары без просмотров не включаются.

Витрина отправляет `POST /api/storefront/products/:id/view` при открытии товара. Сервер засчитывает не более одного просмотра в календарный день по Москве на посетителя. Гость определяется cookie/устойчивым идентификатором браузера; при настроенном `BOT_TOKEN` подписанный Telegram `initData` проверяется и используется ID пользователя, общий для его устройств. Непроверенный Telegram ID не считается подтверждённой личностью. Старые накопленные просмотры сохраняются. Загрузка каталога и админка счётчик не увеличивают.

В финансовом блоке статистики можно выбрать месяц и нажать на выручку, себестоимость, прибыль или средний чек для просмотра графика по дням. Используются даты заказов и ручных продаж; склад показывает текущие остатки независимо от выбранного месяца. Себестоимость ручных продаж неизвестна. В редакторе товара доступны отдельные краткое и полное описания; кнопки «Ж», «К», H2, H3 и ¶ применяют форматирование. Жирный текст хранится как `**текст**`, курсив — `_текст_`; отображение проверяется в предпросмотре.

## Документ закупки

«Создать документ» → «Закупка» открывает категории слева и документ справа. Выберите категорию, затем товары внутри неё; кнопка «Все категории» возвращает список категорий. Поиск помогает найти категорию по названию или товару в ней. Укажите поставщика, добавьте товары, количество и цену в целых рублях. Поля «Магазин» в закупке нет; данные старых документов сохраняются. На вкладке «Счета и оплата» задаётся оплаченная сумма; по умолчанию — 0. Итог и долг рассчитываются автоматически. Доступны комментарий и печать документа.

Снимите «Документ проведён», чтобы сохранить черновик без изменения склада и финансов. Сохранённые закупки доступны в разделе «Бухгалтерия»: черновик можно открыть, изменить и провести. Проведение атомарно добавляет остатки, заменяет закупочную цену каждого товара ценой из документа и создаёт один расход на оплаченную сумму. Повторная отправка того же нового документа не начисляет остатки повторно. У существующего документа есть «Изменить документ». Изменение/отмена проведения/удаление пересчитывает разницу остатков и связанную оплату одной транзакцией. Если получится отрицательный остаток, сервер отклоняет всё изменение. Отдельные счета последующих оплат не реализованы.

## GAS Mini App

Витрина доступна на `/miniapp`, админка — на `/`. Оформление следует предоставленному эталону GAS SHOP: тёмно-бордовый фон с прежним абстрактным узором, белая компактная шапка с круглым значком, три красные информационные плитки, широкий баннер, светлая панель категорий с горизонтальной прокруткой, две колонки светлых карточек с чёрными ценами и закреплённая навигация «Главная / Корзина». Максимальная ширина содержимого — 432 пикселя. Бордовый узор заполняет всё окно Mini App, включая боковые области на широком экране, и повторяется плиткой 520 × 520 CSS-пикселей без растягивания. Затемнение при открытии модального окна также покрывает всё окно. Основные панели слегка прозрачные; открытая шторка товара использует glass-эффект с размытием фона. Сумма и баланс в шапке скрыты до подключения баланса покупателя. Круглый значок GAS открывает профиль.

Контент берётся из админки, примеры товаров и баннеров в рабочую базу не добавляются. Фотографии товаров заполняют одинаковую квадратную рамку по центру без растягивания и пустых полей. В подробностях товара несколько фото можно листать свайпом, точками или стрелками на ПК. Фото, название, цена и стрелка карточки открывают страницу товара, выезжающую снизу на высоту окна; добавить товар в корзину можно в подробностях. Дополнительных кнопок поверх фотографий нет. На плитках «Важно прочитать», «Реферальная программа» и «Отзывы» используются локальные SVG. Названия и порядок категорий берутся из админки. Выбранная категория выделена белой плашкой, остальные подписи серые. Стрелка справа убрана; категории листаются свайпом или горизонтальной прокруткой, активная вкладка центрируется.

Все активные баннеры показаны в бесконечной горизонтальной карусели по ID: доступны свайпы влево/вправо, стрелки на ПК и индикаторы. Автопереход выполняется после 7 секунд покоя; после ручного листания отсчёт начинается заново. Автолистание приостанавливается при касании, открытом окне или скрытой вкладке. Последний и первый баннер соединены в обе стороны без обратного пролистывания всей ленты. Нажатие открывает подробности выбранной акции. При одном баннере навигация скрыта, при отсутствии активных баннеров блок скрыт целиком. В админке «Редактирование → Баннеры» можно загрузить JPG, PNG или WebP до 10 МБ; рекомендуемый размер 1200 × 675 (16:9). Изображение уменьшается до 1200 пикселей, сохраняется в SQLite и загружается отдельным кешируемым запросом `/api/banner-images/ID?v=HASH`. В JSON панели и витрины передаётся только ссылка; при замене картинки ссылка меняется. В карусели все баннеры имеют один размер 16:9: изображение заполняет рамку без растяжения, лишние края обрезаются по центру. Полное изображение с исходными пропорциями доступно в подробностях акции. Текстовый баннер занимает такую же рамку. Заголовок остаётся альтернативным текстом картинки; нажатие открывает изображение и подробное описание акции внутри приложения. Старая ссылка сохраняется в базе, но витрина по ней не переходит. После удаления картинки возвращается текстовый вариант. Старые баннеры сохраняются при автоматической миграции базы. Если активных баннеров нет, блок скрывается полностью. Для точного совпадения фотографий и рекламы с эталоном нужны исходные изображения, загруженные через админку.

Анимации появления, нажатий, переключения категорий и вкладок профиля сохранены. Плашка категории перемещается за 320 мс, каталог переключается горизонтальным пролётом за 380 мс; быстрые нажатия оставляют последнюю выбранную категорию. При `prefers-reduced-motion: reduce` движение отключается. Панель категорий имеет высоту 46 пикселей, нижняя навигация — 240 × 60 пикселей.

Корзина — отдельная вкладка с изменением количества, удалением, суммой и счётчиком. Она сохраняется в localStorage с разделением по Telegram ID или как гостевая. При загрузке цены обновляются из админки, недоступные позиции удаляются, количество ограничивается остатком и 999 единицами на позицию. Товары не резервируются. При возврате на главную сохраняются категория и прокрутка. Профиль показывает имя из Telegram, текущую корзину и реферальные условия; личная история заказов пока недоступна.

Публичный `/api/storefront` выдаёт `shop`, `products`, `banners`, `categories`, `referral` и опубликованные `reviews`, без закупочных цен и данных клиентов. Скрытые товары, отзывы и баннеры не выдаются. Изменения админки видны при открытии или перезагрузке витрины. Telegram `initData`-авторизация, оформление заказов, платежи и автоматические реферальные начисления ещё не подключены. Данные Telegram используются только для отображения и разделения локальной корзины, а не для доступа к приватным данным.

На телефонах в Telegram с поддержкой WebApp API 8.0 запрашивается полноэкранный режим; повторный запрос доступен кнопкой «На весь экран». На ПК запрос полного экрана отключён, кнопка скрыта, а ранее включённый полный экран закрывается через API, если клиент это поддерживает. В остальных клиентах используется `expand()`. Интерфейс учитывает безопасные отступы Telegram. Цвета верхней панели, фона и нижней панели задаются в бордовый цвет, в том числе через нативный мост при недоступном SDK.

Для подключения в Telegram разместите приложение за HTTPS и укажите `https://ВАШ-ДОМЕН/miniapp` в BotFather. Официальный Telegram WebApp SDK загружается асинхронно и не задерживает запуск каталога. Если SDK ещё не загрузился, страница отправляет `web_app_ready` через доступный нативный мост Telegram или в родительское окно Telegram Web, чтобы показ интерфейса не зависел от внешнего скрипта. Если SDK недоступен, витрина работает в гостевом режиме; при поздней загрузке SDK восстанавливаются профиль и отдельная корзина пользователя Telegram. Встраивание витрины в Telegram Web разрешено, админка сохраняет запрет встраивания. Административные пароли и cookie нельзя передавать в Mini App.

Проверка Mini App на временной базе:

```bash
PLAYWRIGHT_MODULE=/tmp/shop-browser/node_modules/playwright/index.mjs node tests/miniapp-smoke.mjs
```

Браузерная проверка покрывает профиль, корзину, сохранение и восстановление, актуализацию цен и остатков, баннеры, переключение категорий, мобильную компоновку, гостевой режим без Telegram и недоступный localStorage. Команда `npm run test:browser` также проверяет загрузку и удаление картинки баннера в админке.

Создание товара: сортировка по умолчанию — 100; начальный остаток — 0, поступление добавляется закупкой. Прежние остатки и порядок товаров сохраняются. Удаление товара убирает его из панели и витрины, сохраняя историю документов. При удалении категории её товары остаются без категории. Сохранение блокирует повторные нажатия, повторяет тот же ключ при ошибке и показывает понятную ошибку сети или тайм-аут через 20 секунд.

`npm run test:workflows` проверяет полный сценарий с несколькими фото, ошибкой и повтором сохранения, удалением товаров и категорий, закупкой по категориям, баннером произвольных пропорций, галереей и проверкой полноэкранного API Telegram.

Загрузка: CSS, JavaScript, HTML и SVG подготавливаются при запуске, передаются с gzip при поддержке браузером и проверяются по ETag, поэтому неизменившиеся файлы возвращаются без повторной передачи. После изменения файлов интерфейса перезапустите сервер. Ответы API остаются `no-store`. Витрина прекращает ожидание зависшего ответа через 15 секунд и предлагает повторить; панель различает ошибку сети и отсутствие авторизации. Проверка и смена пароля выполняются асинхронно с ограничением параллельной работы, чтобы вход не блокировал остальные страницы. Некорректные URL возвращают HTTP 400. При повреждённом старом фото приложение сохраняет исходную запись и выводит предупреждение вместо отказа всего сервера.

Защита загрузки каталога: HTML выдаётся с `no-store`, адреса JavaScript и CSS содержат хеш содержимого, чтобы Telegram не смешивал старый скрипт с новой разметкой. Ошибки необязательных методов Telegram SDK не останавливают загрузку каталога. При ошибке витрина различает HTTP-статус, отсутствие соединения, тайм-аут, неверный ответ и сбой отображения; кнопка «Повторить» повторяет загрузку. Отсутствующие в старом ответе категории определяются из товаров; отсутствующие массивы баннеров и отзывов считаются пустыми.

Производительность истории: позиции заказов загружаются одним запросом вместо отдельного запроса на каждый заказ. Итоги повторно используются для показателей клиентов и финансов, включая историю удалённых клиентов. Сжатие gzip применяется также к JSON-ответам от 1 КБ, если браузер его поддерживает; оно выполняется асинхронно, ответы сохраняют `Cache-Control: no-store`. Индекс метаданных фотографий включает идентификатор фото, чтобы список галерей читался без загрузки самих изображений. Проверки финансовой совместимости — `tests/order-history.test.js`, сжатия — `tests/loading.test.js`.

## Витрина и журнал операций

- Поле остатка отсутствует при создании и редактировании товара. API сохраняет текущий остаток при редактировании и отклоняет прямое изменение количества; приход оформляется закупкой. Архивация отделена от переключателя видимости в боте.
- «Товары → Управление категориями»: порядок меняется перетаскиванием или стрелками. «Сохранить порядок» сохраняет последовательность для панели, закупок и Mini App. «Все товары» остаётся первым пунктом витрины. Панель категорий закрепляется сверху при прокрутке.
- Фотографии заполняют одинаковую квадратную рамку: пропорционально увеличиваются от центра до исчезновения пустых полей, лишние края обрезаются. Товар открывается выезжающей снизу страницей с сохранённой галереей. На ПК компактные SVG-стрелки появляются по бокам фото при наведении; внизу поверх фотографии расположены серые точки без цифрового счётчика; активная — белая вытянутая полоска. На телефоне стрелки скрыты, фотографии листаются свайпом или нажатием на точки.
- Аватар клиента отображается в шапке и профиле из HTTPS-поля Telegram `photo_url`. Если Telegram не передал фото или изображение недоступно, сохраняется значок/инициалы. Аватар используется для отображения; идентификатор для суточных просмотров принимается только из подписанных данных Telegram при настроенном серверном `BOT_TOKEN`.
- В редакторе баннера добавлено подробное описание акции до 10 000 символов. Нажатие на баннер открывает окно с изображением, заголовком, подзаголовком и описанием; внешнего перехода нет.
- Раздел «Операции» показывает единый журнал закупок, продаж/заказов, списаний и прочих записей с датой, контрагентом, статусом и суммой. Есть поиск, фильтры и экспорт. Документ закупки или заказа открывается из строки. Оплата закупки остаётся в финансовом учёте, но не дублирует её в журнале. Статистика остаётся отдельным разделом.

`npm run test:miniapp-updates` проверяет новый сценарий в браузере: порядок категорий, журнал документов, акции, аватар, цвета оболочки, полноэкранный режим, центрирование фотографий, страницу товара и закрепление категорий.

Шторка товара закрывается свайпом вниз от верхнего положения содержимого. Крестик закрытия отображается только на ПК; на телефонах он скрыт. Короткое или отменённое движение возвращает шторку на место; горизонтальное листание фотографий и прокрутка длинного описания работают отдельно. За ручку можно потянуть мышью. Пока шторка открыта, вертикальные жесты оболочки Telegram временно отключаются; при закрытии прежнее состояние восстанавливается. `npm run test:gestures` проверяет карусель и шторку настоящими сенсорными событиями браузера.

## Продажи, операции и карточка товара

Документы создаются основной кнопкой слева; отдельной кнопки создания в журнале нет. «Продажа» использует тот же выбор категорий/товаров, что закупка, с ценами продажи и покупателем. Проведение уменьшает остаток, отмена/удаление возвращает его. Для себестоимости сохраняется цена на момент продажи. Продажи входят в статистику без повторного учёта связанной оплаты. В журнале доступны изменение и удаление закупок, продаж, старых ручных операций и заказов. Удалённые записи сохраняются в базе, но исключаются из журнала и расчётов. Старый заказ редактируется своим редактором статуса.

Для новых закупок сохраняется предыдущая закупочная цена. При удалении/изменении документа цена берётся из последней действующей закупки либо сохранённого предыдущего значения с учётом отменённых закупок. Для старых документов без снимка исходной цены сохраняется последняя известная цена, если восстановить её из истории невозможно.

Под фото рядом с названием товара размещены кнопка с самолётиком Telegram и надписью «Поделиться», а на ПК — также крестик закрытия. Кнопка открывает выбор чата Telegram через `openTelegramLink` и `t.me/share/url`; системное меню iOS/Android не используется. Ссылка открывает нужный товар через `startapp=product_ID`; имя бота задаётся в настройках магазина. Нажатия сопровождаются лёгким откликом через Telegram HapticFeedback, когда клиент и настройки устройства это поддерживают. Pinch/double-tap масштабирование отключено в Mini App. Для оставшихся ошибок открытия нужен ролик с воспроизведением; автоматическая проверка включает серию повторных открытий и закрытий.

`npm run test:refinements` проверяет создание/редактирование/удаление продаж и закупок через интерфейс, видимость, центрирование фото с полями, галерею, кнопки под фото, шаринг, суточные просмотры и haptic-отклик.

Шторка товара использует светлую полупрозрачную поверхность с размытием фона; если браузер не поддерживает backdrop-filter, остаётся светлая подложка. Кольцо фокуса скрыто после касания/клика и сохраняется при навигации клавиатурой.

В каталоге, открытой карточке и галерее используется одна квадратная рамка. Любое фото пропорционально масштабируется от центра до полного заполнения (`cover`, центр 50% 50%); выходящие за рамку края обрезаются. Высота рамки не зависит от пропорций источника. Равномерные белые/прозрачные края исходника предварительно убираются для отображения без добавления новых полей. Оригинальные файлы в базе не изменяются.

Акция открывается отдельным окном с полным крупным изображением и крестиком поверх него; фон за окном затемнён и размыт. Описание показано под изображением, если заполнено. Текст-заглушка отсутствует; у баннера без описания и подзаголовка открывается только изображение. `npm run test:banners` проверяет таймер на виртуальных часах, бесконечный переход, паузу при открытом окне/скрытой вкладке и расположение крестика.
