# Учет товара — панель управления магазином

Панель на основе shop с голубым интерфейсом по предоставленному образцу: боковое меню, показатели, компактная таблица с закупочной ценой и вложениями (остаток × закупочная цена), формы и мобильная навигация. Данные из исходного магазина не копируются.

Веб-панель для магазина обычных товаров: каталог, клиенты, заказы, управленческие финансы, модерация отзывов, условия реферальной программы, информация о магазине и баннеры. Интерфейс на русском, адаптивная вёрстка, поиск, фильтры и CSV-экспорт. Node.js 24+ и SQLite без внешних runtime-зависимостей и сборки.

## Запуск

```bash
cd /workspace/ruslan
node --version # нужен Node.js 24 или новее
npm run admin:create
npm start
```

Сервер по умолчанию слушает `127.0.0.1:3000`. Команда создания администратора генерирует случайный пароль и сохраняет логин и пароль в `.data/initial-admin.txt` с правами `0600`. Сохраните их в менеджере паролей и удалите файл. Повторный вызов не меняет существующий аккаунт.

Можно создать аккаунт с собственными `ADMIN_USERNAME` и `ADMIN_PASSWORD` (не менее 12 символов), передав их через безопасную среду процесса команды `npm run admin:create`. Не добавляйте секреты в Git. Эти переменные не нужны работающему серверу.

```bash
npm run dev    # перезапуск при изменениях сервера
npm run check  # проверка синтаксиса
npm test       # интеграционные тесты HTTP API с отдельной временной БД
```

Опциональная проверка интерфейса в Chromium (временная БД, рабочие данные не меняются):

```bash
npm install --prefix /tmp/shop-browser --no-package-lock --no-audit --no-fund playwright
PLAYWRIGHT_MODULE=/tmp/shop-browser/node_modules/playwright/index.mjs npm run test:browser
```

По умолчанию браузер берётся из `/usr/bin/chromium`; другой исполняемый файл можно задать через `CHROMIUM_PATH`. Переменная `SCREENSHOT_DIR` позволяет сохранить снимки входа, каталога и мобильной версии. Playwright нужен только для этого дополнительного теста.

Каждая облачная задача уже изолирована. Используйте существующий checkout; не создавайте Git worktree без явного запроса пользователя.

## Страницы товаров и клиентов

- Товары: вкладки категорий и создание категории, поиск и фильтры, собственное фото, название, сохранение порядка в колонке «Сортировка», цена и закупка, количество, вложения, рейтинг опубликованных отзывов и их просмотр, редактирование и удаление. Нажатие на заголовки позволяет сортировать по названию, цене или заданному порядку.
- Клиенты: создание и редактирование, телефон, сумма заказов без отменённых, количество и дата последнего заказа; статусы «Активный», «В ожидании», «Заблокирован». Есть поиск по имени, телефону или ID, фильтры по статусу, сумме покупок и числу заказов, выбор строк, массовое удаление и CSV-экспорт текущей выборки.
- Удаление скрывает товары и клиентов из рабочих списков; связанные заказы, отзывы и история сохраняются. Миграции базы применяются автоматически при запуске и сохраняют существующие данные.
- «Создать документ» открывает список «Продажа», «Закупка», «Списание» с документами продажи, закупки и списания. Продажа и списание создают финансовые операции без изменения остатков. Закупка содержит товары: при проведении увеличивает остатки и обновляет закупочные цены, а оплаченная сумма записывается в расходы. В «Статистике» остаются оценка склада, выручка, себестоимость, валовая прибыль, средний чек и заказы. Показатели клиентов находятся в «Клиентах», рефералов — в «Реферальной программе». Сводка отзывов убрана.

## Что реализовано

- **Статистика:** оценка склада по закупочной цене (включая архив), выручка по выполненным заказам и ручным продажам, известная себестоимость заказов, валовая прибыль, средний чек и статусы заказов. Себестоимость ручных продаж без состава товаров неизвестна и не включается.

- **Товары:** создание, редактирование, категории, цены в целых рублях, остатки, загрузка своих фотографий JPG/PNG/WebP, скрытие на витрине, массовое скрытие, поиск, фильтры, страницы, экспорт текущей выборки.
- **Клиенты:** список, поиск, история заказов, статус блокировки. Это флаг для будущей интеграции; Telegram Mini App пока не подключён.
- **Заказы:** состав, способ получения, клиент и изменение статуса. Остатки редактируются вручную: приём новых заказов и резервирование требуют будущего API оформления заказа.
- **Финансы:** выполненные заказы учитываются как поступления ровно один раз; ручные доходы и расходы; результат с вычетом себестоимости проданных товаров. Это управленческий учёт, не бухгалтерская/налоговая отчётность и не платёжный сервис.
- **Отзывы:** публикация и скрытие.
- **Реферальная программа:** сохранение условий и отображение приглашений. Автоматическое начисление, выплаты и учёт referral-кодов при регистрации ещё не реализованы.
- **Редактор:** контакты, описание, заголовок магазина, создание/редактирование/удаление баннеров, видимость, цвет и ссылка.
- **Аккаунт:** вход и выход; настройки аккаунта скрыты из интерфейса.

По умолчанию магазин **полностью пустой**: товары, клиенты, заказы, отзывы, финансовые операции, приглашения и баннеры не создаются. Контакты и описание магазина пусты; реферальная программа отключена, её суммы равны нулю. Учётная запись администратора создаётся отдельно. Перезапуск сохраняет введённые вами данные и не добавляет примеры. Тестовые записи создаются только явно внутри изолированных тестов, не в рабочей базе.

## API для будущего Telegram Mini App

`GET /api/storefront` — публичное представление сохранённой витрины: `shop`, `products`, `banners`. Скрытые товары и баннеры, закупочные цены, клиенты, заказы и финансовые данные не выдаются. `stock` — текущий остаток. Поле `image` содержит фотографию в виде data URL или пустую строку; старые ключи иллюстраций остаются совместимыми с API, но интерфейс показывает для них заглушку. Фото автоматически уменьшается до 1200 пикселей; исходный файл — до 10 МБ. Фотографии сохраняются в SQLite вместе с товаром.

Административные маршруты требуют cookie-сессию. После `POST /api/auth/login` сервер возвращает CSRF-токен; передавайте его в `X-CSRF-Token` для всех изменений. `GET /api/auth/me` восстанавливает состояние сессии; `GET /api/bootstrap` загружает данные панели. CRUD поддерживает создание и редактирование товаров и баннеров, статусы клиентов/заказов/отзывов, ручные финансовые операции и настройки.

Витрина Mini App и локальная корзина реализованы (см. раздел GAS Mini App ниже). Telegram `initData`-авторизация, оформление заказов, бот, платежи и доставка — следующий этап. Для них потребуются отдельные серверные маршруты и проверки. Административные cookie и пароли нельзя передавать в Mini App.

## Хранение и размещение

- `DB_PATH` — путь к SQLite, по умолчанию `.data/shop.db` относительно приложения. Для команды `admin:create` запускайтесь из корня проекта; используйте одинаковый `DB_PATH` для сервера и CLI.
- `HOST` — по умолчанию `127.0.0.1`; для контейнера можно задать `0.0.0.0`.
- `PORT` — по умолчанию `3000`.
- `COOKIE_SECURE=true` — обязательно при размещении за HTTPS reverse proxy. Оставьте выключенным только для локальной проверки HTTP.
- БД и файлы WAL должны находиться на постоянном диске с ограниченным доступом. Снимайте согласованные резервные копии SQLite. Не копируйте только `shop.db` у работающего процесса без учёта WAL.
- Пароли хешируются scrypt с индивидуальной солью. Сессии на 12 часов хранятся в БД по хешу токена; cookie — `HttpOnly`, `SameSite=Strict`. Изменения защищены CSRF-токеном, проверяется Origin, вход ограничен по числу неудачных попыток.
- В первой версии нет ролей сотрудников, MFA и журнала действий. Перед публичным запуском настройте HTTPS, резервное копирование, мониторинг и правила доступа. Вход защищает API; публичный API витрины выдаёт только необходимые покупателю поля.

Приложение не требует сетевых запросов к CDN, внешних шрифтов или npm-пакетов при запуске. Опубликовать приложение на домене и настроить Telegram нужно отдельно.

## Архив и описание

По умолчанию в товарах показаны только позиции в работе. Фильтр «Архив» открывает архивные позиции; кнопка «Восстановить» возвращает тот же товар с прежним ID, отзывами и историей. Для нескольких позиций есть массовое архивирование и восстановление. Ранее скрытые товары считаются архивными.

Фото в таблице обрезается по центру в квадрат и заполняет всю область. В редакторах описания товара и магазина доступны H2, H3 и цвет выделенного текста с предпросмотром. Формат хранится как текст: `## Заголовок`, `### Подзаголовок`, `[color=#087fff]текст[/color]`. HTML из описания не исполняется. Потребителям API следует отображать этот ограниченный формат с экранированием текста.

## Просмотры товаров

В «Статистике» показаны выручка, известная себестоимость, валовая прибыль, средний чек, статусы заказов, топ-10 товаров по просмотрам и оценка склада. Оценка склада включает количество единиц, стоимость по розничным и закупочным ценам (включая архив), а также предупреждение о товарах с остатком и нулевой закупочной ценой. Показатели клиентов и рефералов находятся в своих разделах; сводки отзывов здесь нет. Топ-10 расположен внизу слева, оценка склада — справа; на узких экранах блоки идут друг под другом. Рейтинг учитывает сохранённые просмотры за всё время, независимо от выбранного месяца; товары без просмотров не включаются.

Витрина должна отправлять `POST /api/storefront/products/:id/view` один раз при фактическом открытии карточки товара. Авторизация администратора не требуется. Загрузка каталога и действия в админке не увеличивают счётчик. Просмотры сохраняются в SQLite; прежние просмотры не восстанавливаются, уникальность посетителей не определяется. Внешнюю витрину необходимо подключить к этому endpoint: её код в этом репозитории отсутствует.

В финансовом блоке статистики можно выбрать месяц и нажать на выручку, себестоимость, прибыль или средний чек для просмотра графика по дням. Используются даты заказов и ручных продаж; склад показывает текущие остатки независимо от выбранного месяца. Себестоимость ручных продаж неизвестна. В редакторе товара доступны отдельные краткое и полное описания; кнопки «Ж», «К», H2, H3 и ¶ применяют форматирование. Жирный текст хранится как `**текст**`, курсив — `_текст_`; отображение проверяется в предпросмотре.

## Документ закупки

«Создать документ» → «Закупка» открывает выбор товаров слева и документ справа. Укажите поставщика и магазин, добавьте товары, количество и цену в целых рублях. На вкладке «Счета и оплата» задаётся оплаченная сумма; по умолчанию — 0. Итог и долг рассчитываются автоматически. Доступны комментарий и печать документа.

Снимите «Документ проведён», чтобы сохранить черновик без изменения склада и финансов. Сохранённые закупки доступны в разделе «Бухгалтерия»: черновик можно открыть, изменить и провести. Проведение атомарно добавляет остатки, заменяет закупочную цену каждого товара ценой из документа и создаёт один расход на оплаченную сумму. Повторная отправка того же нового документа не начисляет остатки повторно. Проведённые документы доступны только для просмотра; отмена проведения и последующие оплаты отдельными счетами пока не реализованы.

## GAS Mini App

Витрина доступна на `/miniapp`, админка остаётся на `/`. Дизайн GAS в красно-белом стиле: компактная шапка, три квадратные графические плитки, один баннер, горизонтальная панель категорий и товары в две колонки. Ширина витрины ограничена 480 пикселями, как у мобильного Mini App; снизу закреплена навигация «Главная / Корзина». Кнопка профиля в шапке открывает окно с затемнением фона, именем из Telegram, текущей корзиной и условиями реферальной программы. Имя используется только для отображения, а не для доступа к приватным данным. Оба интерфейса используют одну SQLite-базу. Вверху — «Важно прочитать» (описание и контакты магазина), условия реферальной программы и опубликованные отзывы. Далее отображаются первый активный баннер по ID, категории и активные товары в заданном порядке. Категории фильтруют каталог; карточка показывает описания, цену, наличие и регистрирует просмотр. При отсутствии данных отображается пустое состояние, примеры в рабочую базу не добавляются.

Публичный `/api/storefront` дополнен `categories`, `referral` и `reviews` без сведений о клиентах. Скрытые отзывы и товары не выдаются. Изменения админки видны при загрузке или перезагрузке страницы витрины. Цвет баннера на витрине красный в соответствии со стилем GAS.

Для подключения в Telegram разместите сервер за HTTPS и укажите `https://ВАШ-ДОМЕН/miniapp` в настройках Mini App / кнопки меню бота через BotFather. Подключён официальный Telegram WebApp SDK (ready, expand, цвета); без SDK витрина продолжает работать в браузере. Разрешено встраивание витрины в Telegram Web, админка сохраняет запрет встраивания. Доступ к `telegram.org` нужен клиентскому браузеру для SDK. Корзина работает локально: добавление кнопкой «+» на карточке каталога и из открытых подробностей товара, изменение количества, удаление, сумма и счётчик. Она сохраняется в localStorage с разделением по Telegram ID (или как гостевая); при загрузке цены берутся из админки, недоступные позиции удаляются, количество ограничивается остатком и 999 единицами на позицию. Выбранные товары не резервируются. Оформление заказов, платежи, серверная проверка Telegram initData и автоматические реферальные начисления пока не реализованы. Профиль показывает количество и сумму текущей корзины, а не неподтверждённую историю покупок.

Проверка Mini App на временной базе:

```bash
PLAYWRIGHT_MODULE=/tmp/shop-browser/node_modules/playwright/index.mjs node tests/miniapp-smoke.mjs
```

Плитки «Важно прочитать», «Реферальная программа» и «Отзывы» перерисованы в SVG по предоставленным изображениям и доступны без внешнего CDN. Анимированы появление элементов, нажатия, открытие/закрытие окон, добавление в корзину и счётчики. При `prefers-reduced-motion: reduce` движение отключается. Браузерная проверка Mini App дополнительно проверяет профиль, корзину, сохранение и восстановление, актуализацию цен/остатков, гостевой режим без Telegram и недоступный localStorage.

Ориентир интерфейса Mini App — [LOOP SHOP (@loopshopapp)](https://t.me/loopshopapp) и предоставленные пользователем скриншоты магазина. При дальнейших изменениях сверяйте компактную компоновку, три квадратные плитки, горизонтальные категории, две колонки товаров, закреплённую навигацию и профиль с затемнением фона. Для GAS сохраняются красно-белые цвета, один баннер из админки и навигация «Главная / Корзина». Поиска в Mini App нет; поиск в админке сохраняется.

Категории Mini App переключаются горизонтальным пролётом за 380 мс с лёгким размытием и световыми полосами: текущая сетка уходит, а новая одновременно въезжает с другой стороны. Направление зависит от порядка категорий; при быстрых повторных нажатиях остаётся последняя выбранная категория. При включённом уменьшении движения переключение происходит без анимации.

Карточки в каталоге оформлены по референсу LOOP SHOP: светло-серый фон, крупное квадратное фото, фото без метки категории, название, красная цена и стрелка справа. Фото, название и цена открывают подробности товара. Отдельная кнопка «+» на фото добавляет товар в корзину без открытия подробностей; добавление также доступно в открывшемся окне. Цена показывается точно из админки без префикса «от», поскольку вариантов с разными ценами пока нет.

Название в шапке Mini App — GAS SHOP. На панели категорий остаются только категории, без отдельного значка рубля; цены товаров отображаются в рублях.

Панель категорий и нижняя навигация повторяют овальную форму и пропорции с предоставленного скриншота LOOP SHOP. Категории объединены в капсулу высотой 50 пикселей с вкладками по 40 пикселей, нижняя навигация — 288 × 60 пикселей. Сохранена красная палитра, панели слегка прозрачные: активная категория — красная плашка с жирным белым текстом (font-weight: 900), остальные подписи красные. Плашка плавно перемещается к выбранной вкладке и меняет ширину за 320 мс. Кнопки панели сохраняются при переключении, выбранная категория плавно прокручивается к центру. Подложка корректируется при изменении размеров окна; уменьшение движения отключает анимацию. Тайминги анимации остались прежними; точное совпадение с живым LOOP SHOP не подтверждено.

Поверхности Mini App плоские, с лёгкой прозрачностью: панели пропускают около 6% фона, карточки товаров — 5%. Размытие фона, стеклянные блики и светящиеся кромки убраны; текст и кнопки сохраняют полную непрозрачность. Знак ₽ в суммах имеет обычное начертание. Вкладки профиля меняются плавно, без перерисовки карточки пользователя; в «Обзоре» есть раскрываемый блок «Последние заказы». Личная история заказов ещё не подключена: без серверной проверки Telegram initData и связи с клиентом админки показывается «История заказов пока недоступна». Приватные заказы в публичный API не добавляются.

Панель баннера находится непосредственно под тремя информационными плитками и использует то же скругление. Она показывает первый активный баннер из админки. Если активных баннеров нет, блок скрывается полностью и его старое содержимое очищается. Данные загружаются при открытии или перезагрузке страницы витрины.

Корзина — отдельная вкладка Mini App, а не модальное окно. На обеих страницах остаётся видна нижняя навигация «Главная / Корзина». При возврате на главную сохраняются выбранная категория и позиция прокрутки; изменение количества, удаление и сумма работают прямо на странице корзины. Профиль и подробности товара по-прежнему открываются в модальных окнах; переход из них в корзину сначала закрывает окно.

Фон витрины — бесшовный тёмно-бордовый векторный узор с плавными формами и тонкими линиями по предоставленному образцу. Плитка повторяется по всей ширине и высоте страницы с постоянным размером 520 × 520 CSS-пикселей: узор не растягивается и не обрезается как изображение с cover. На карточках товаров метки категорий убраны; фильтрация по категориям остаётся в верхней панели. Стеклянные поверхности имеют светлую подложку для читаемости на красном фоне.

Узор ограничен экраном приложения шириной до 480 пикселей и отделён тонкой границей. На широких экранах пространство за пределами этой области чёрное; на телефоне приложение занимает доступную ширину. Повторение и масштаб узора сохраняются на обеих вкладках и по всей длине каталога.
