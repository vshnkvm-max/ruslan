# Запуск GAS SHOP на VPS

Инструкция для нового VPS/VDS с Ubuntu 24.04 LTS и root-доступом, например в AdminVPS или Timeweb Cloud. Рекомендуется 1–2 vCPU, 2 ГБ памяти и 20 ГБ постоянного SSD. Приложению нужен Node.js 24; внешних npm-зависимостей и сборки нет.

Команды ниже выполняются **на вашем VPS от root через SSH или консоль провайдера**. Настройка виртуального хостинга Optimo отличается: поддержка Timeweb подтвердила, что запуск веб-сервера Node.js там запрещён.

Приложение работает от отдельного пользователя `gas-shop`. Код находится в `/opt/gas-shop`, база — в `/var/lib/gas-shop/shop.db`. Служба systemd запускает приложение после перезагрузки и перезапускает при сбоях.

## 1. Подготовить домен и доступ

Создайте DNS-запись **A** для выбранного домена или поддомена, указав публичный IPv4 VPS. Например: `shop.example.ru → IP вашего VPS`. Дождитесь обновления DNS. Если для этого же имени существует запись AAAA, она должна указывать на работающий IPv6 этого сервера.

В сетевом экране провайдера разрешите входящие TCP-соединения на **80** и **443**, а также SSH-порт сервера (обычно **22**). Node.js будет слушать только `127.0.0.1:3000` внутри VPS.

Подключитесь к VPS:

```bash
ssh root@IP_ВАШЕГО_VPS
```

Ниже везде замените `shop.example.ru` на свой домен. Протокол `https://` и путь `/miniapp` в имя домена не входят.

## 2. Установить Node.js 24 и необходимые программы

```bash
apt-get update
apt-get install -y ca-certificates curl git nginx certbot python3-certbot-nginx sqlite3

curl -fsSL https://deb.nodesource.com/setup_24.x -o /tmp/gas-shop-node24.sh
bash /tmp/gas-shop-node24.sh
apt-get install -y nodejs

node --version
npm --version
```

`node --version` должен показать `v24.x.x`. Официальный установщик NodeSource подключает репозиторий с проверкой подписи пакетов. При ошибке скачивания или установки устраните её перед переходом дальше; отключать проверку TLS или подписей не требуется.

## 3. Скачать код и подготовить базу

```bash
git clone --branch main https://github.com/vshnkvm-max/ruslan.git /opt/gas-shop
cd /opt/gas-shop
npm run check
npm test

id -u gas-shop >/dev/null 2>&1 || useradd --system --user-group --home-dir /var/lib/gas-shop --create-home --shell /usr/sbin/nologin gas-shop
install -d -o gas-shop -g gas-shop -m 0700 /var/lib/gas-shop

```

`npm install` для работы приложения не нужен. Если каталог `/opt/gas-shop` уже существует, используйте раздел обновления ниже вместо повторного клонирования. Для приватного репозитория сначала потребуется настроить на VPS доступ к GitHub.

Если магазин уже заполнен на другой машине, данные через GitHub не переносятся: **сейчас, до создания администратора и запуска службы**, перенесите согласованную резервную копию SQLite в `/var/lib/gas-shop/shop.db` и назначьте владельца `gas-shop:gas-shop` с правами `0600`. Прежние аккаунты сохранятся. У работающей SQLite нельзя копировать один файл `shop.db`, игнорируя WAL; используйте SQLite `.backup`, как в разделе резервного копирования. Для нового магазина этот перенос не требуется, база будет пустой.

Теперь создайте администратора:

```bash
runuser -u gas-shop -- env DB_PATH=/var/lib/gas-shop/shop.db /usr/bin/node /opt/gas-shop/scripts/create-admin.js
```

Команда создаёт администратора `admin` со случайным паролем. Данные входа находятся в **`/var/lib/gas-shop/initial-admin.txt`** с правами `0600`. Откройте этот файл лично через SFTP или редактор, сохраните пароль в менеджере паролей и удалите файл после сохранения. Не отправляйте пароль в чат и не добавляйте его в Git. Повторное создание администратора не меняет существующую учётную запись.

## 4. Включить постоянный запуск

```bash
install -m 0644 /opt/gas-shop/deploy/gas-shop.service /etc/systemd/system/gas-shop.service
systemctl daemon-reload
systemctl enable --now gas-shop
systemctl status gas-shop --no-pager
curl --retry 10 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:3000/api/health
```

Проверка должна вернуть `{"ok":true}`. Если служба не запустилась, посмотрите причину:

```bash
journalctl -u gas-shop -n 100 --no-pager
```

В конфигурации уже указаны постоянный путь базы и `COOKIE_SECURE=true` для доступа через HTTPS. Закрытие терминала не останавливает службу.

## 5. Подключить Nginx и HTTPS

Укажите свой домен:

```bash
SHOP_DOMAIN=shop.example.ru
sed "s/SHOP_DOMAIN/${SHOP_DOMAIN}/g" /opt/gas-shop/deploy/nginx.conf > /etc/nginx/sites-available/gas-shop
ln -s /etc/nginx/sites-available/gas-shop /etc/nginx/sites-enabled/gas-shop
nginx -t
systemctl enable --now nginx
systemctl reload nginx

certbot --nginx --redirect -d "$SHOP_DOMAIN"
systemctl enable --now certbot.timer
certbot renew --dry-run

curl -fsS "https://${SHOP_DOMAIN}/api/health"
curl -fsS "https://${SHOP_DOMAIN}/api/storefront"
```

Certbot запросит контактный email и согласие с условиями центра сертификации. Он выпустит сертификат и настроит перенаправление на HTTPS. Для выпуска домен уже должен вести на VPS, а порт 80 — быть доступен из интернета.

Если символьная ссылка Nginx уже существует, повторять `ln -s` не нужно. Перед перезагрузкой Nginx его проверка `nginx -t` должна завершиться успешно.

Входите в админку после настройки HTTPS: в службе включены защищённые cookie.

- Админка: **`https://shop.example.ru/`**.
- Витрина: **`https://shop.example.ru/miniapp`**.
- Проверка сервера: **`https://shop.example.ru/api/health`**.

Откройте админку, войдите, создайте товар и проверьте его появление на витрине. Фотографии и картинку баннера можно загрузить через админку.

## 6. Подключить Telegram

В **@BotFather** выберите своего бота, откройте настройки кнопки меню (`/setmenubutton`) и укажите:

```text
https://shop.example.ru/miniapp
```

Это подключает существующую витрину и локальную корзину. Серверная авторизация Telegram, оформление заказов и платежи пока не реализованы; подробнее — в README.

## Резервное копирование и обновление

Перед обновлением создайте согласованную копию SQLite. Команда `.backup` учитывает данные из WAL и подходит для работающего приложения:

```bash
install -d -m 0700 /var/backups/gas-shop
SHOP_BACKUP="/var/backups/gas-shop/shop-$(date +%Y%m%d-%H%M%S).db"
sqlite3 -readonly /var/lib/gas-shop/shop.db ".backup '$SHOP_BACKUP'"
chmod 0600 "$SHOP_BACKUP"
sqlite3 -readonly "$SHOP_BACKUP" 'PRAGMA integrity_check;'
```

Последняя проверка должна вернуть `ok`. Храните дополнительные копии на отдельной машине или в закрытом облачном хранилище: база содержит данные магазина и учётных записей.

Для обновления кода установите `umask 022`, чтобы новые файлы мог читать пользователь службы `gas-shop`. Строгую маску `077` для резервной копии задавайте только в отдельной подоболочке `(umask 077; команда)`, иначе она повлияет и на последующий `git pull`.

```bash
cd /opt/gas-shop
umask 022
git pull --ff-only origin main
npm run check
npm test
systemctl restart gas-shop
curl --retry 10 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:3000/api/health
```

Если `git pull` или проверки завершились ошибкой, устраните её до перезапуска. База лежит вне репозитория; миграции применяются автоматически при старте приложения. Обновление галереи переносит старые фото товаров в отдельную таблицу той же базы, сохраняя товары, остатки и сортировку. Перед первым запуском новой версии обязательно сделайте резервную копию по инструкции выше: для отката к старому коду понадобится и прежняя база. Новых зависимостей и изменения Nginx для этого обновления не требуется: каждое фото загружается отдельным небольшим запросом.

Если при обновлении изменились файлы `deploy/gas-shop.service` или `deploy/nginx.conf`, проверьте изменения и перенесите нужные настройки в `/etc`. После изменения службы выполните `systemctl daemon-reload` и `systemctl restart gas-shop`; после изменения Nginx — `nginx -t` и `systemctl reload nginx`. Nginx-конфигурация в `/etc` после выпуска сертификата содержит добавленные Certbot настройки HTTPS — сохраняйте их при обновлении.

Сжатие файлов интерфейса и ETag работают в Node.js без дополнительной настройки Nginx. После обновления нужен перезапуск `gas-shop`, чтобы загрузить новые файлы интерфейса. Баннеры остаются в существующей таблице SQLite; новая версия выдаёт изображения отдельными запросами, поэтому повторная загрузка старых баннеров не нужна.

Обновление витрины добавляет описание акции и ссылку закупки на её оплату. Перед обновлением сделайте резервную копию по инструкции выше. Миграция сохраняет существующие остатки, документы и суммы; старые оплаты связываются только при однозначном совпадении записи. Новых пакетов и изменений Nginx не требуется.

Обновление документов продаж и видимости требует резервной копии SQLite перед первым запуском. Миграция сохраняет архив и накопленные просмотры, а для товаров без остатка выключает видимость. В последующих изменениях остатка видимость обновляется автоматически. Перед откатом старой версии восстановите соответствующую копию базы.

Для единого учёта просмотров одного Telegram-пользователя на нескольких устройствах задайте `BOT_TOKEN` в окружении службы VDS (например через закрытый файл окружения systemd). Не передавайте токен в браузер, GitHub или чат. Без токена работает суточный учёт по браузеру. Имя бота для ссылок задаётся отдельно в панели «Редактирование» → «Бот для ссылок на товары».

Настройка подгонки фото добавляет колонку `products.image_fit` с начальным значением `auto`. Перед обновлением сделайте копию SQLite. Миграция сохраняет фотографии, товары, остатки и документы. Старые клиенты, не передающие это поле, сохраняют уже выбранный режим.

Обновление условий реферальной программы добавляет процентную составляющую в существующую настройку SQLite. Перед обновлением сделайте резервную копию. Прежние заданные суммы, минимальная выплата и флаг включения сохраняются. Для старых незаполненных условий 0 ₽ / 0 ₽ фиксированная часть становится 100 ₽; процент по умолчанию — 5%. Повторные запуски не перезаписывают сохранённые значения, включая нулевые.

## Заказы и отдельный бот

В корзине доступны «Продолжить покупки» и «Оформить заказ». Оформление открывает шторку со списком, итогом, подтверждением и отменой. Подтверждение сохраняет заказ в разделе **Заказы** админки и резервирует товары. Отмена заказа в админке возвращает остатки; восстановление снова проверяет наличие. Старые заказы сохраняют прежний порядок учёта остатков. Завершённый заказ уже учитывается в поступлениях: создавать для него отдельную продажу не нужно.

Уведомления отправляются **отдельным ботом в личные чаты менеджеров из белого списка username**. Вручную указывать `ORDER_CHAT_ID` не требуется. Каждый менеджер отправляет `/start`, приложение проверяет username и сохраняет его Telegram ID. Несколько подключённых менеджеров получают каждый новый заказ; подключившийся позже не получает уже доставленную историю. Накопленные неотправленные заказы начнут отправляться после первого подключения.

Все команды ниже выполняются **на VDS от root**. Node.js переустанавливать не нужно.

**1. Создайте отдельного бота.** В Telegram откройте **@BotFather**, отправьте `/newbot`, задайте название и свободный username нового бота. Сохраните выданный токен. Основной бот с Mini App и отдельный бот уведомлений — два разных бота. Для уведомлений используйте нового бота без webhook и других программ, читающих `getUpdates`.

**2. Узнайте username менеджера.** Он находится в настройках его Telegram, например `@manager_one`. Нужен именно username, а не отображаемое имя и не username бота. Менеджер должен иметь username. Для нескольких менеджеров перечислите имена через запятую.

**3. Обновите код и сохраните резервную копию базы:**

```bash
cd /opt/gas-shop
umask 022
apt-get install -y sqlite3
(umask 077; sqlite3 -readonly /var/lib/gas-shop/shop.db ".backup '/root/gas-shop-before-managers-$(date +%Y%m%d-%H%M%S).db'")
git pull --ff-only origin main
npm run check
```

**4. Запишите настройки:**

```bash
touch /etc/gas-shop.env
chmod 600 /etc/gas-shop.env
nano /etc/gas-shop.env
```

В файле должны быть строки с вашими настоящими значениями:

```dotenv
BOT_TOKEN=ТОКЕН_ОСНОВНОГО_БОТА_С_MINI_APP
ORDER_BOT_TOKEN=ТОКЕН_НОВОГО_БОТА_ДЛЯ_ЗАКАЗОВ
ORDER_MANAGER_USERNAMES=manager_one,manager_two
ORDER_CHAT_ID=
```

Для одного менеджера укажите только его имя: `ORDER_MANAGER_USERNAMES=manager_one`. Регистр и начальный `@` не важны; проще записывать без `@` и пробелов. `ORDER_CHAT_ID=` оставьте пустым: непустой старый ID имеет приоритет и включает прежний ручной режим. Токены не отправляйте в чаты и не сохраняйте в Git. В nano сохраните файл: **Ctrl+O → Enter → Ctrl+X**.

**5. Подключите настройки к службе и перезапустите приложение:**

```bash
mkdir -p /etc/systemd/system/gas-shop.service.d
cat > /etc/systemd/system/gas-shop.service.d/telegram.conf <<'EOF'
[Service]
EnvironmentFile=/etc/gas-shop.env
EOF
systemctl daemon-reload
systemctl restart gas-shop
systemctl status gas-shop --no-pager -l
curl --max-time 5 -f http://127.0.0.1:3000/api/health
```

Служба должна быть `active (running)`, проверка — вернуть `{"ok":true}`.

**6. Подключите менеджера.** Со своего разрешённого аккаунта менеджер открывает **нового бота заказов** и отправляет `/start` в личном чате. В течение нескольких секунд бот ответит: «Вы подключены к уведомлениям о заказах GAS SHOP». Каждый менеджер из списка делает это отдельно. В группе привязка не работает. Посторонние аккаунты не подключаются и уведомлений не получают. Обновите страницу «Заказы» в админке: сообщение об ожидании подключения должно исчезнуть.

**7. Проверьте заказ.** Откройте Mini App из основного бота, добавьте товар, нажмите «Оформить заказ» → «Подтвердить». Заказ должен появиться в админке и в личных чатах подключённых менеджеров. Отмените тестовый заказ в админке, чтобы вернуть товар на склад. В обычном браузере можно собрать корзину, но подтверждать заказ нужно из Telegram: сервер проверяет подписанные данные покупателя основным токеном.

Сообщение содержит номер заказа, покупателя, Telegram ID, ссылку для связи, позиции, количество, цены и итог. Отсутствие username у **покупателя** не мешает оформлению. Белый список нужен только менеджерам.

Если бот не отвечает на `/start`: проверьте username аккаунта, `ORDER_MANAGER_USERNAMES`, пустую строку `ORDER_CHAT_ID=`, токен нового бота и исходящий HTTPS-доступ сервера к `api.telegram.org:443`. Перезапускайте службу после изменения файла. Не подключайте этот бот одновременно к другой программе или webhook: они мешают получению `/start`. Для диагностики службы: `journalctl -u gas-shop -n 50 --no-pager`.

Для проверки без вывода токенов выполните от root:

```bash
cd /opt/gas-shop
node scripts/check-order-bot.js --env-file /etc/gas-shop.env --db /var/lib/gas-shop/shop.db
```

Проверка сравнивает настройки файла с окружением **запущенной** службы, показывает username бота уведомлений, наличие webhook, число подключённых менеджеров и размер очереди. Она не отправляет сообщения, не читает `getUpdates`, не изменяет webhook и открывает базу только для чтения. Результат можно передать для диагностики: значения токенов и URL webhook скрыты. Если настройки службы отличаются от файла, повторите шаг 5. Если бот в выводе отличается от бота, которому менеджер отправлял `/start`, проверьте `ORDER_BOT_TOKEN`.

В разделе «Заказы» админки и в журнале службы теперь показывается причина ошибки: неверный токен, конфликт получения команд, отсутствие username в белом списке, запрет отправки или недоступность Telegram. Повторяющиеся одинаковые ошибки не засоряют журнал. Короткие коллекционные username и список имён с разделением пробелом или точкой с запятой также поддерживаются.

Привязки и очередь хранятся в SQLite и переживают перезапуск. Username проверяется при подключении, далее используется сохранённый числовой Telegram ID. Передача уже привязанного username другому аккаунту не заменяет менеджера автоматически. Чтобы отозвать доступ, удалите исходный username из списка и перезапустите службу. Если нужно намеренно передать его другому Telegram-аккаунту, потребуется отдельно сбросить старую привязку.

Недоступность Telegram не задерживает оформление: заказ сохранится в админке, а сервер повторит отправку с задержкой. Для каждого менеджера очередь хранит отдельный результат доставки. При неоднозначном сетевом обрыве Telegram может получить сообщение повторно — сверяйте номер заказа. Повтор подтверждения покупателем возвращает тот же заказ и не списывает остатки второй раз.

Прежняя настройка с числовым `ORDER_CHAT_ID` также работает. В этом режиме команда `npm run orders:bot-info` помогает узнать ID личного чата после `/start`; автоматическая регистрация по username отключена.

Настройки реферальной программы сами по себе не начисляют вознаграждения за эти заказы: привязка приглашений и начисления — отдельная функция.

## Оплата рублями с баланса

В шторке подтверждения заказа нажмите «Списать рубли» и выберите сумму ползунком. Лимит — не более 50% стоимости товаров и не больше текущего баланса. При нулевом балансе кнопка недоступна. Выбранная сумма сразу уменьшает «К оплате», а фактическое списание происходит только после подтверждения заказа. Отмена шторки не изменяет баланс.

Отмена или удаление заказа в админке возвращает списанные рубли. При восстановлении отменённого заказа сервер снова проверяет баланс и остатки; если их недостаточно, восстановление не произойдёт. Повторное подтверждение, в том числе после потерянного ответа, возвращает существующий заказ без нового списания.

Обновление добавляет поля заказа и таблицу истории движений баланса, сохраняя старые заказы со списанием 0 ₽. Перед `git pull` и перезапуском сохраните базу:

```bash
(umask 077; sqlite3 -readonly /var/lib/gas-shop/shop.db ".backup '/root/gas-shop-before-rubles-$(date +%Y%m%d-%H%M%S).db'")
```

Правила начисления кешбэка и реферальных бонусов этим изменением не включаются. Суммы на пользовательские балансы автоматически не добавляются.

## Установить рубли клиенту вручную

1. В админке откройте **Клиенты**, затем карточку нужного клиента.
2. В блоке **«Рубли на балансе»** нажмите **«Установить баланс»**. Также можно нажать на сумму в колонке «Баланс» списка клиентов.
3. Впишите итоговый остаток в целых рублях и сохраните. Например, значение 1000 установит баланс 1000 ₽. Можно уменьшить сумму или обнулить её.
4. Клиент увидит новый остаток после возвращения в Mini App или обновления страницы. Для отображения выбирайте запись, связанную с Telegram ID: она создаётся при оформлении заказа из бота. Вручную заполненный username не связывает запись с Telegram-аккаунтом.

Если клиент успел потратить рубли, пока форма открыта, панель покажет свежий остаток и попросит проверить сумму перед повторным сохранением. При потере ответа поле временно фиксируется: повтор сохранения проверяет прежний запрос и не перезаписывает последующие списания. Внизу формы есть последние ручные изменения с датой и администратором. Ручная корректировка баланса не считается денежной выручкой.

Обновление добавляет таблицу истории `customer_balance_adjustments`, сохраняя текущие остатки и историю оплаты заказов. Перед обновлением сохраните базу обычной командой SQLite `.backup`, затем выполните `git pull --ff-only origin main`, `npm run check` и `systemctl restart gas-shop`.

## Отзывы с фото и видео

Обновление добавляет таблицу файлов отзывов и сохраняет время первого выполнения заказа. Текущие товары, заказы, балансы и отзывы сохраняются. Дата выполнения старых заказов неизвестна: для них используется дата создания. У новых заказов семь суток отсчитываются от первого перевода в статус «Выполнен».

Перед обновлением сделайте резервную копию:

```bash
(umask 077; sqlite3 -readonly /var/lib/gas-shop/shop.db ".backup '/root/gas-shop-before-reviews-$(date +%Y%m%d-%H%M%S).db'")
cd /opt/gas-shop
umask 022
git pull --ff-only origin main
npm run check
```

В **существующий HTTPS-блок `server { ... }`** файла `/etc/nginx/sites-enabled/gas-shop` добавьте строку (если её ещё нет):

```nginx
include /opt/gas-shop/deploy/review-uploads.conf;
```

Она должна находиться внутри того блока, где настроен `listen 443 ssl`, вне `location`. Сохраните текущие сертификаты и настройки TLS. Не заменяйте действующий конфиг целиком шаблоном для нового сервера. Include увеличивает лимит до 25 МБ и таймаут до 90 секунд **только для загрузки вложений отзывов**; остальные API сохраняют прежний лимит. Для новой установки строка уже есть в `deploy/nginx.conf`.

```bash
nginx -t && systemctl reload nginx
systemctl restart gas-shop
systemctl status gas-shop --no-pager -l
curl --max-time 5 -f http://127.0.0.1:3000/api/health
```

Каталог `/var/lib/gas-shop/review-media` создаётся службой автоматически при первой загрузке, владелец — `gas-shop`, права каталога `0700`, файлов `0600`. Nginx получает файлы через приложение, прямой доступ к каталогу ему не нужен. Токен **основного бота** `BOT_TOKEN` должен быть настроен: им проверяются покупатель и подписанные ссылки. Отдельный бот заказов и доступ к Telegram API для загрузки отзывов не требуются.

Проверка: завершите заказ в админке → откройте «Отзывы» в Mini App от аккаунта покупателя → «Оставить отзыв» → выберите товар, оценку, фото и видео → отправьте → опубликуйте в админке. Проверьте общую ленту, фильтр «С медиа» и блок в карточке товара. Если при загрузке появляется `413`, проверьте include именно в HTTPS-блоке.

Медиа нужно сохранять вместе с резервной копией SQLite. Для согласованной копии приостановите запись:

```bash
systemctl stop gas-shop
(umask 077; tar -C /var/lib/gas-shop -czf /root/gas-shop-with-media-$(date +%Y%m%d-%H%M%S).tar.gz shop.db review-media)
systemctl start gas-shop
```

Архив с `review-media` выполняйте после первой загрузки, когда каталог существует. При восстановлении назначьте владельца `gas-shop:gas-shop`, каталогу права `0700`, файлам `0600`. Не удаляйте каталог медиа при обычном обновлении кода.

## Личные заказы и начисления

Обновление профиля использует существующие таблицы заказов и аудита баланса. После обычного обновления кода перезапустите `gas-shop`. Новых переменных окружения для этой функции нет, требуется настроенный основной `BOT_TOKEN` для проверки покупателя.

Проверка: профиль → «Заказы» → открыть новый тестовый заказ со списанием рублей → «Отменить заказ» → подтвердить. В админке должен измениться статус того же заказа, остатки и баланс должны восстановиться. В профиле → «Начисления» должны быть отдельные записи списания и возврата. Выполненный заказ доступен для просмотра без кнопки отмены. Изменения баланса через админку также попадают в историю. Автоматические правила кэшбека и реферальных начислений остаются отдельной задачей.
